# Sung Yandex

Нативный музыкальный плеер для Linux: интерфейс **Sung / Qt Quick / Material 3**,
каталог **Yandex Music** и совместимый с **yamusic** дисковый кэш.

## Быстрый запуск на NixOS

```sh
cd ~/projects/sung-yandex
./scripts/run-yandex.sh
```

Скрипт входит в Nix-окружение и собирает актуальную Release-версию в `build-release`.
Если нет сохранённого токена, но рядом есть `../yamusic/.env`, он использует оттуда `YANDEX_MUSIC_TOKEN`
только для чтения. Файл не копируется и не исполняется как shell-код.
Для другого расположения задайте `YANDEX_MUSIC_ENV_FILE=/path/to/.env`.

Можно ввести OAuth-токен в **Settings → Connections → Yandex Music**.
При включённом **Remember in system keyring** токен хранится в системном
Secret Service через `secret-tool` (libsecret); нужен запущенный и разблокированный
GNOME Keyring или совместимый сервис. Без этой опции подключение действует
до закрытия приложения. Поддерживаются также ключ `yamusic` в системном keyring,
`YANDEX_MUSIC_TOKEN` и явно заданный `YANDEX_MUSIC_ENV_FILE`. Явное окружение
имеет приоритет над keyring, автоматический поиск соседнего `.env` — после него.
**Disconnect and forget saved token** удаляет ключ Sung и отключает автоматический
вход до следующего подключения; исходный ключ yamusic и `.env` не меняются. Нужны действующий аккаунт и доступ
к прослушиванию музыки; ограничения сервиса сохраняются.

Отдельная воспроизводимая сборка с Qt-обёрткой:

```sh
nix build
./result/bin/sung-yandex
```

## Что работает

- Поиск треков, альбомов, исполнителей и плейлистов Yandex Music.
- Сердечки синхронизируются с аккаунтом; создание, переименование, удаление
  собственных плейлистов, добавление, удаление и перестановка их треков.
  Изменения отображаются после подтверждения сервера; конфликт ревизий
  требует обновить плейлист, а не перезаписывает изменения другого устройства.
- Полный каталог исполнителя с постраничной загрузкой **Load more**, альбомы
  и плейлисты аккаунта на главной.
- Отдельная страница **Моя волна** в навигации: цветная GPU-анимация на основе
  шейдера yamusic и обложка по центру. Цвета следуют обложке, анимация реагирует
  на звук и лайк. Управление остаётся в нижнем баре; Play на странице запускает волну.
  При скрытии страницы/окна анимация выключается; учитывается настройка движения.
  Кнопка «Настроить» задаёт занятие, характер, настроение и язык волны, как в
  официальном клиенте; выбор сохраняется, а играющая волна сразу перезапускается.
  Прямой вход: `./scripts/run-yandex.sh --my-wave`.
- Персональная **My Wave** и радио от трека: сессии Yandex, продолжение очереди
  и обратная связь о прослушивании и пропусках.
- Вставка ссылок `music.yandex.ru` на трек, альбом, исполнителя или плейлист.
- Lossless через `get-file-info`, включая ответы без поля `size`.
- Воспроизведение через Qt Multimedia, очередь, перемотка, MPRIS, интерфейс Sung.
- Новый трек начинает играть по HTTPS, загрузка на диск идёт отдельно.
- Автоматическое или ручное сохранение на диск, отключение загрузок и лимит кэша.
- **Home → Downloaded · Offline**: доступ к скачанному без токена и сети.
- Обложки и LRC сохраняются для офлайн-доступа, когда доступны у сервиса.
- Локальные файлы и плейлисты Sung, включая смешанные коллекции.

API и формат кэша перенесены из Rust-кода `yamusic` в небольшой Python-адаптер
стандартной библиотеки. Интерфейс и аудиоплеер остаются нативными C++/QML.
Sung передаёт адаптеру JSON через stdin/stdout отдельного процесса.

## Кэш

Порядок выбора каталога:

1. `YANDEX_MUSIC_CACHE_DIR`;
2. `cache-dir` из `$XDG_CONFIG_HOME/yamusic/config.toml` (обычно `~/.config/yamusic/config.toml`);
3. `$XDG_CACHE_HOME/yamusic` (обычно `~/.cache/yamusic`).

Формат совместим с исходной репой: `<id>.<codec>` и `<id>.meta.json`.
Сначала проверяется диск; OAuth и API для попадания в кэш не нужны.
Загрузка записывается в уникальный `.tmp`, проверяется и атомарно переименовывается.
Плеер получает hardlink в свой временный каталог, либо копию, если файловые системы
разные. Закрытие плеера не удаляет оригинал из кэша.

В **Settings → Connections → Yandex Music** доступны режимы **Automatic / Manual / Off**.
При первом запуске учитывается `cache` из yamusic (`hotkey` → Manual, `off` → Off).
Настройка в интерфейсе имеет приоритет. В ручном режиме используйте **Save offline**
в меню трека или **Save current track offline**. Off запрещает новые аудиозагрузки,
но уже сохранённые треки по-прежнему воспроизводятся.

По умолчанию лимита общего размера нет. Можно выбрать 4 или 16 GiB аудио:
после загрузок вытесняются старые файлы по времени последнего использования;
**Apply limit and free space** запускает очистку сразу. Текущий трек защищён,
поэтому размер временно может превышать лимит. Кэш общий с yamusic — удаление
затрагивает скачанное обоими приложениями. Лимит одного файла — 512 MiB.
**Clear cache** Sung по-прежнему не удаляет эту музыкальную библиотеку.

Обложки хранятся в `artwork/`, тексты — в `lyrics/<id>.lrc`. Они скачиваются
после фонового сохранения аудио; **Download artwork and lyrics for cached songs**
дополняет уже существующий кэш. Отсутствие текста у сервиса не мешает сохранять
и слушать аудио. Лимит аудио не учитывает размер обложек. Статус и отмена загрузок
доступны в том же разделе настроек.

## Сборка без Nix

Нужны C++20, CMake 3.24+, Ninja, Python 3.11+, FFmpeg и Qt 6.8+
(Core, Gui, Quick, Qml, QuickControls2, Multimedia, Network, DBus, Svg, ShaderTools).
Для Wayland и обложек установите плагины Qt Wayland и imageformats.
Для сохранения токена нужны libsecret (`secret-tool`) и Secret Service.

```sh
./scripts/setup.sh
./scripts/build.sh
./build/sung-yandex
# Необязательная установка в ~/.local:
./scripts/install.sh
```

Python-пакеты из PyPI для Yandex не нужны. Имена приложения, настроек,
MPRIS и установленного helper отделены от оригинального Sung.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_yandex*.py' -v
nix develop -c cmake -S . -B build -G Ninja -DBUILD_TESTING=ON
nix develop -c cmake --build build --target sung sung-tests -j 4
nix develop -c ctest --test-dir build -R '^(yandex-helper|backend)$' --output-on-failure
```

Тесты адаптера не требуют сети или аккаунта: проверяют совместимость кэша,
повторное воспроизведение, незавершённые загрузки, идентификаторы, подписи,
ошибки авторизации и протокол процессов, keyring, конфликты плейлистов,
сессии «Моей волны», офлайн-обложки/LRC и вытеснение кэша. Нативные тесты
проверяют подтверждение удалённых изменений, пагинацию и продолжение/отмену волны. В `BackendTest` есть проверка реального
воспроизведения и перемотки FLAC из кэша без учётных данных через Qt Multimedia.

Проверено на живом API: все 142 трека исполнителя (100 + 42), чтение библиотеки,
операции с отдельным временным приватным плейлистом (после проверки удалён),
две партии «Моей волны», загрузка и последующее офлайн-чтение обложки и LRC.
Необязательный тест `yandexLiveStreaming` проверяет HTTPS-воспроизведение и
перемотку через Qt с пустым кэшем; обычный прогон не обращается к аккаунту.

## Условия работы

Онлайн-каталог, синхронизация и «Моя волна» требуют доступного Yandex API и
действующего аккаунта. Сервис может не предоставлять отдельный трек, обложку
или текст. Для офлайн-доступа дождитесь окончания загрузки; одна лишь запись
трека в очереди не означает, что он сохранён. Сохранившееся аудио играет без токена.

Плейлисты Yandex принимают только треки Yandex. Для местных файлов или смешанной
коллекции выбирайте **This device** при создании плейлиста. Загрузка собственной
обложки и другие локальные настройки оформления Sung не меняют оформление в Yandex.
YouTube-каталог заменён на Yandex Music.
